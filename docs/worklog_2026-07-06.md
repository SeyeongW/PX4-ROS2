## 1. 정밀착륙 시스템

### 노드
| 파일 | 역할 |
|------|------|
| `camera_detection/camera_detection/aruco_pose_node.py` | 캘리브레이션(solvePnP) 기반 ArUco pose → `/perception/marker_pose`(카메라 프레임 tvec, m) |
| `precision_landing/precision_landing/precland_hw_node.py` | GUIDED 속도 서보 정밀착륙 (IDLE→ALIGN→DESCEND→LAND). 정지 마커 전용 |
| `precision_landing/launch/precland_hw.launch.py` | MAVROS + 카메라 + 검출 + 제어 일괄 |

### 동작
- `auto_takeoff=false`(기본): 조종사가 **① 시동 → ② 이륙 후 GUIDED → ③ 마커 위로 이동** → 자동 정렬·하강·착륙
- 터치다운: 공중 강제 disarm 대신 **ArduPilot LAND 모드 인계** (평지 안전)
- 안전: GUIDED 이탈/disarm 시 즉시 셋포인트 중단(조종사 회수)
- 로그가 조종사를 단계별로 안내 (엣지 트리거 + 3초 리마인더). `/precision_landing/debug` 로도 발행

### 실행 (젯슨)
```bash
ros2 launch precision_landing precland_hw.launch.py \
    fcu_url:=/dev/ttyACM0:115200 \   # FC C-to-C USB 연결 시
    marker_size:=<마커 실측 m>
# 카메라는 기본 camera_driver:=usb_cam (icSpring MJPG 1280x720)
```

## 2. 카메라

### 현재 카메라: icSpring USB (USB id `32e6:9221`, `/dev/video0`)
- **720p 는 MJPG 전용** (YUYV 는 640x480 만) → `v4l2_camera` 는 MJPG 디코딩 불가(크래시)
- **`usb_cam`(ros-humble-usb-cam) 사용**, `pixel_format:=mjpeg2rgb`
- 수동 실행:
  ```bash
  ros2 run usb_cam usb_cam_node_exe --ros-args \
      -p video_device:=/dev/video0 -p pixel_format:=mjpeg2rgb \
      -p image_width:=1280 -p image_height:=720 -p framerate:=30.0
  ```

### 캘리브레이션 (icSpring, 1280x720)
- `camera_calibration cameracalibrator --size 8x6 --square 0.03` (체커보드 3cm, 태블릿 표시)
- 결과: fx=578.25, fy=579.59, cx=666.82, cy=395.65 (HFOV ≈ 96°, 광각), plumb_bob 왜곡
- 저장 위치:
  - 레포: `camera_detection/config/down_camera.yaml` (런치가 이걸 사용)
  - 젯슨: `~/.ros/camera_info/default_cam.yaml` (usb_cam 이 /camera_info 자동 발행)
- **주의**: 런치는 **설치본**(`install/.../down_camera.yaml`)을 사용 → 소스 수정 시 `colcon build` 필요
- **주의**: 카메라 바꾸면 재캘리브레이션 필수 (이전 캠 fx=717 값은 폐기)

### 체커보드 도구
- 생성기: `camera_detection/tools/gen_checkerboard.py`
- 인쇄용 SVG: `camera_detection/config/checkerboard_8x6_25mm.svg`
- 태블릿 표시용 PNG: `camera_detection/config/checkerboard_8x6_display.png` (화면 칸 크기 자로 재서 `--square`)

## 3. DDS 네트워크 (FastRTPS + Discovery Server over Tailscale)

### 배경
- 기존: CycloneDDS + Tailscale(peers XML). 유지보수 부담(머신마다 peer 편집) + PX4 uXRCE-DDS 브릿지 포기하고 MAVROS 전환의 원인.
- **PC + 젯슨을 FastRTPS 로 전환** (`.bashrc`의 RMW_IMPLEMENTATION=rmw_fastrtps_cpp). CycloneDDS/URI 는 주석 보존.
- Tailscale 은 멀티캐스트 안 되므로 **Discovery Server**(유니캐스트)로 원격 디스커버리.

### Tailscale IP
| 머신 | tailscale IP |
|------|--------------|
| PC | 100.110.148.7 |
| 젯슨 (이 프로젝트) | 100.112.65.33 |
| 다른 젯슨 (Cyclone 대상) | 100.110.98.82 |

### 젯슨 = Discovery Server (systemd, 상시)
- 서비스: `fastdds-discovery.service` (enabled, 부팅 자동실행, Restart=always)
- 래퍼: `/usr/local/bin/fastdds_discovery_server.sh` → `exec /usr/bin/fast-discovery-server -i 0 -p 11811` (0.0.0.0:11811)
  - ※ systemd 에선 `fastdds discovery` 파이썬 래퍼 대신 **`fast-discovery-server` 바이너리 직접** 호출 (전자는 "tool not found" 발생)
- 젯슨 `~/.bashrc`: `export ROS_DISCOVERY_SERVER="127.0.0.1:11811"` (서버가 자기 자신에 있어 localhost)
- → **젯슨은 켜기만 하면 서버 자동 실행 + 노드 자동 등록.** 재부팅해도 유지.
- 재시작 주의: 실제 프로세스명은 `fast-discovery-server`(하이픈). 잔재 정리는 `sudo pkill -9 -f fast-discovery-server` (포트 11811 점유 시 새 인스턴스 "Server creation failed").

### PC 스위처 스크립트 (`~/`, git 밖 = 개인 설정)
| 스크립트 | 용도 |
|----------|------|
| `~/dds_fastdds.sh` | 이 젯슨(FastRTPS+DS). `ROS_DISCOVERY_SERVER=100.112.65.33:11811` + super_client + **자기 tailscale IP 자동감지** 화이트리스트(`~/.fastdds_tailscale.gen.xml`). 다른 PC 에 복사만 하면 그대로 동작 |
| `~/dds_cyclone.sh` | 다른 젯슨(100.110.98.82)/팀. CycloneDDS + `~/cyclonedds_pc.xml`(peers: PC + 100.110.98.82) |
| `~/dds_local.sh` | 로컬 멀티캐스트(원격 설정 전부 해제) |
- 각 스크립트는 다른 모드 env 를 unset + `ros2 daemon stop`. `.bashrc`엔 안 박음(상황별 `source`).

### 사용
```bash
# PC — 이 젯슨과 작업
source ~/dds_fastdds.sh
ros2 topic list        # 젯슨 토픽 보임

# 다른 사람이 붙으려면: 같은 tailnet 가입 후 dds_fastdds.sh 복사 → source (IP 편집 불필요)
```

### 검증됨
- PC 를 tailscale 인터페이스로 강제한 상태에서 젯슨 `/chatter` 수신 확인 → 데이터가 tailscale 로 흐름(다른 망에서도 동작).
